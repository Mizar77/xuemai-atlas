# 人物资料与关系完整性审计协议

本协议用于人物新增或重点人物复审。目标不是声称“互联网中不存在更多信息”，而是在明确检索边界、来源等级和复核日期的前提下，给出可重复的高覆盖结果。

## 多代理交叉审计

每位重点人物至少由三个相互独立的检索角色复审：

1. **学术谱系代理**：检索博士/硕士论文、学校学位库、CV、导师及实验室校友页，核验上游导师、共同导师、博士后导师和下游培养关系。
2. **团队与人才流动代理**：完整遍历当前组员、历届博士与博士后名单，区分第一份工作与当前任职，并用接收单位官方页面复核明显的后续跳槽。
3. **产业与科研影响代理**：核验学术任职时间线、企业任职、创业、联合实验室、资助、奖项、公开研究方向和有明确证据的长期合作。

主审代理负责姓名消歧、人物去重、时间冲突处理和最终合并。不同代理的共同结论不替代一手来源；每一条公开关系仍必须带可访问的证据链接。

## 必查维度

- 姓名、中文名、当前机构、职称与是否休假/兼职
- 本科、硕士、博士、博士后经历及导师
- 当前研究主题与公开招生状态
- 当前博士生、博士后及明确共同指导者
- 完整公开校友名录、毕业年份、第一份工作和当前去向
- 学术界任职、企业任职、创业与联合实验室
- 代表性奖项、资助、社区或研究组织角色
- 能由官方记录证明的长期合作或共同项目
- 头像及其原始来源

## 关系纳入规则

- **师承**：论文元数据、学位论文正文、学校官方 alumni 页面、导师或学生本人 CV/主页明确写出 adviser/supervisor。
- **共同指导**：双方实验室、学生本人主页或学校新闻明确写出 co-advised/co-supervised。
- **长期合作**：必须有联合实验室、共同项目、持续共同指导或官方长期合作说明；单篇普通合著不构成关系。
- **人才流动**：区分 `first_job` 与 `current`，不得把多年以前的去向当成现职。
- **产业关系**：区分全职、兼职、访问、研究资助和创业，不把奖项或 fellowship 写成雇佣。

## 完成条件

重点人物只有在下列条件同时满足后才可标记为“本轮审计完成”：

- 身份、现职、教育和研究方向均至少有一条一手来源；
- 上游导师检索已完成，并记录 `verified` 或明确的 `deferred` 原因；
- 公开团队/校友页面已逐项遍历，给出覆盖分母；
- 产业履历和高影响去向已进行当前状态复核；
- 所有新增关系通过端点、重复 ID、来源字段和构建检查；
- 报告保留检索日期、已核验项、未公开项与待复核项。

## 新增人物必须原子化交付

从现在起，新增 PI 或重要关系节点不能只提交姓名和关系边。一次新增必须同时完成：

- 在人物数据中写入 `introducedAt`，自动进入严格质量门禁；
- 至少两条学校、本人主页、学位论文或研究组等一手/权威来源；
- 至少四条事实，且必须包含“当前任职”“研究主线”“教育与学术训练”；
- 从学校、实验室或本人主页取得头像原图，保存为本地 512×512 JPEG；
- 人工检查头像身份、构图与清晰度，排除截图、群照、Logo、默认头像和错配；
- 运行 `npm run validate:data`、`npm run audit:portraits` 与生产构建。

若一手来源暂时没有公开真人头像，不得使用低置信图片冒充；该人物应保留在显式待办中，不标记为本轮完整交付。`validate:data` 会阻止带 `introducedAt` 但缺少头像或核心事实的新增节点进入发布版本。

“本轮审计完成”表示完成了上述公开来源范围内的系统检索，不表示现实世界中绝对不存在未公开关系。
